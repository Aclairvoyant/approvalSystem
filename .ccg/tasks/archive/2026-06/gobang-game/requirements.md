# 五子棋小游戏需求记录

## 用户原始需求

开发一个新小游戏：五子棋。支持与对象玩，除五子棋基本玩法外，还需要支持悔棋、认输、全局回放等功能。

## 约束与默认解释

- 复用现有游戏大厅、对象关系校验、房间号加入、WebSocket 实时同步能力。
- 用户已选择方案二：五子棋使用独立表，不复用现有 `games` / `game_moves` 作为主数据表。
- 复用现有对象关系校验、移动端游戏入口、STOMP 认证与按房间广播的外围模式。
- 五子棋棋盘为 15x15，房主执黑先手，对象加入后执白后手。
- `gobang_games.board_data` 存当前五子棋棋盘状态，`gobang_moves.move_data` 存每一步落子和特殊动作，支持从历史动作重建回放。
- 悔棋建议采用“请求-同意”模式：一方发起悔棋，对方同意后撤销最近一步；避免单方强制悔棋影响公平性。
- 认输立即结束游戏，对方获胜。
- 全局回放为只读功能，可在对局中或结束后从第一手按顺序播放。
- 前端页面加入 GSAP 动效，用于落子、悔棋、胜利高亮和回放步骤；动画需遵守 Vue 生命周期清理和减少动态效果偏好。

## 双模型分析摘记

- 初始双模型分析倾向复用现有 `games` / `game_moves`，但用户已明确改选独立表方案。
- 方案二复跑时，外部模型输出仍偏离需求；本次设计只采纳其中可复用外围能力、WebSocket 契约、GSAP 生命周期与回放注意点，不采用其复用表建议。
- 现有飞行棋模块存在若干已有风险（棋子数量不一致、服务端信任骰子参数、任务触发重复），本任务不主动扩大修复范围，除非五子棋接入必须绕开这些问题。
